# 2026 上半年工作总结

## 一、总体建设成果

2026 年上半年，Data Foundry 平台围绕“非结构化信息到结构化数据资产”的核心目标，完成了从原型验证到可联调平台的主要能力建设。平台已形成前端交互、业务后端、调度服务、采集 Agent、公共契约和数据库脚本相互配合的多服务架构，主链路覆盖需求定义、宽表建模、任务计划、采集执行、结果回填、数据验收、发布入库和运维监控。

当前平台的建设重点不再局限于页面展示，而是逐步沉淀为以需求、宽表、任务组、采集任务、采集结果、指标映射、验收单、调度规则等核心对象驱动的数据生产闭环。前端通过统一 API Client 和 Next.js 代理层对接后端，后端通过 Spring Boot、MyBatis、MySQL 承载核心业务数据，调度侧预留并接入 XXL-JOB，Agent 侧提供采集执行契约和模拟结果能力，支撑后续替换真实采集算法服务。

## 二、平台主功能链路

### 1. 从业务需求到结构化数据模型

平台支持以项目为业务容器创建和管理采数需求，围绕业务目标、业务边界、数据来源、负责人、验收负责人等信息沉淀需求定义。需求提交后可绑定并维护目标宽表，将业务字段拆分为维度列、指标列、系统列等结构化 schema，为后续任务计划和数据落库提供统一模型。

在数据范围定义方面，平台支持业务日期轴、维度范围、采集参数表、指标分组、Prompt 模板、调度规则等配置。采集参数既可通过手工录入和文件导入形成固定参数行，也支持通过 SQL 查询目标库动态拉取参数行，使任务生成能够面向最新业务范围。

### 2. 从宽表范围到任务计划

平台已实现基于宽表 schema、业务日期、参数行和指标分组的任务计划生成能力。系统可将一个需求下的目标宽表拆解为任务组和采集任务，并通过计划版本、业务日期、分组分区、参数绑定等信息保持任务与宽表行之间的对应关系。

任务计划既支持正式计划落地，也支持试运行。试运行可按业务日期、宽表行、最大行数和操作人限定范围，生成独立的 trial 批次、任务组和采集任务，用于在正式大规模执行前验证 Prompt、参数、指标分组和采集链路。

### 3. 从任务执行到结果回填

平台支持单任务执行、任务组执行、任务重试、任务取消、任务状态同步等操作。执行时系统会基于任务中的 Prompt 快照组装采集请求，调用外部采集服务并绑定下游 collection task id，同时维护本地任务状态和任务组聚合计数。

采集完成后，平台可同步下游任务状态，拉取采集结果并写入 collection_results。结果进一步支持 final report 归一化、明细行解析、指标字段映射和宽表单元格物化，将外部采集结果转化为平台可展示、可验收、可发布的结构化数据。

### 4. 从数据验收到目标表发布

平台已实现验收单能力，支持按需求、宽表、任务组、数据集等维度创建验收任务，记录负责人、审核人、反馈、状态和发布时间。验收流程支持更新、驳回、通过并发布。

发布环节支持将宽表数据写入目标表，并记录发布任务、成功行数、更新行数、跳过行数、失败行数和错误信息。平台还支持宽表与目标表的数据对比，展示目标表是否已存在对应记录、差异状态和行级对比结果。

### 5. 从周期调度到运行监控

平台已建设调度规则和 XXL-JOB 同步链路。后端可根据宽表调度配置和指标分组生成稳定的调度规则，调度服务可向 XXL-JOB 同步任务，并通过 dataCollectJobHandler 接收调度触发，再回调后端完成规则派发、任务组生成和执行。

运维侧已提供平台概览、任务状态统计、数据状态统计、调度触发日志、服务健康摘要、风险卡片等监控能力，为任务运行、数据采集进展、验收进度和异常排查提供统一入口。

## 三、已实现的核心模块

### 1. 多服务工程与基础架构模块

- 完成前端、业务后端、调度服务、Agent 服务、公共契约的多模块拆分。
- 前端采用 Next.js、React、TypeScript、Tailwind CSS，统一通过 API Client 访问平台接口。
- 后端采用 Spring Boot、MyBatis、MySQL，按项目、需求、任务、调度、验收、运维等领域组织代码。
- 公共契约模块沉淀 Agent 执行请求、采集结果、调度任务、XXL-JOB 同步等跨服务 DTO。
- 数据库侧形成 backend 和 scheduler 两类 schema，覆盖账号、项目、需求、宽表、任务组、采集任务、采集结果、指标映射、验收单、发布日志、调度规则和触发日志等表。

### 2. 账号、权限与个人中心模块

- 支持账号注册、登录和当前用户识别。
- 支持账号列表、可分配账号选项、账号角色和状态维护。
- 前端侧根据角色控制部分菜单和功能入口，例如采集任务管理、权限配置等。
- 支持个人中心视图，聚合当前用户相关的项目、需求、采集任务和验收任务。

### 3. 项目与需求管理模块

- 支持项目列表、项目详情和项目创建。
- 支持需求列表、需求详情、需求创建和需求更新。
- 支持需求检索能力，可按关键词、项目、负责人、经办人、状态、宽表等条件过滤，并支持分页和排序。
- 需求对象中沉淀业务目标、业务边界、交付范围、采集策略、负责人、验收人和数据更新模式。
- 兼容历史路由，同时建设 canonical API，逐步统一前后端接口使用方式。

### 4. 宽表建模与采集范围模块

- 支持需求下主宽表创建和宽表配置维护。
- 支持宽表 schema、维度列、指标列、系统列、指标分组、Prompt 模板、业务日期范围、采集覆盖模式等配置。
- 支持宽表行生成、分页查询和行级编辑。
- 支持参数范围通过手工/文件方式维护，也支持 SQL 动态导入和预览。
- 支持目标表列表查询、目标表字段查询和 SQL 查询预览，为参数导入和目标落库提供基础能力。

### 5. 任务计划与任务编排模块

- 支持根据宽表配置生成任务组和采集任务。
- 支持按业务日期、指标分组、参数行等维度拆分任务。
- 支持计划版本、任务组分区、任务总数、待执行数、运行数、成功数、失败数、取消数等运行时计数。
- 支持试运行批次，能够限定范围快速生成并触发采集任务。
- 支持任务计划预览、计划持久化和任务组刷新，为正式执行前的校验提供基础。

### 6. 采集执行与 Agent 集成模块

- 支持任务组执行、单任务执行、重试、取消和状态详情查询。
- 支持幂等键，降低重复触发导致的重复执行风险。
- 支持执行前刷新 Prompt 快照，将参数、业务日期等占位符渲染为实际采集请求。
- 支持对接外部采集服务创建搜索任务、查询状态、取消任务和获取结果。
- Agent 服务提供标准执行入口，支持返回指标结果、检索任务结果、窄表行、final report 和 normalized rows，便于后续替换真实采集能力。

### 7. 采集结果、指标映射与宽表物化模块

- 支持按任务、任务组、宽表查询采集结果。
- 支持 final report 归一化，统一采集结果展示和后续解析基础。
- 支持从采集结果生成指标字段映射，并支持人工调整目标指标 key、指标名称、匹配类型和确认状态。
- 支持将已确认映射的采集结果物化到宽表行 indicator_values 中，形成可验收、可发布的数据单元格。
- 支持保留来源站点、来源链接、引用文本、置信度、原始值、清洗值、最大/最小值等证据字段，增强结果可追溯性。

### 8. 数据验收与发布模块

- 支持验收单列表、创建、更新、驳回。
- 支持验收通过后发布宽表数据到目标表。
- 支持宽表直接发布到目标表，并记录发布任务和行级日志。
- 支持目标表对比，查看已匹配、缺失、失败等状态。
- 支持按验收单和发布任务追踪反馈、审核人、发布时间、发布错误信息等过程数据。

### 9. 调度规则与 XXL-JOB 集成模块

- 支持从宽表调度配置生成调度规则。
- 支持按指标分组生成稳定 rule id、cron 表达式、业务日期偏移和 XXL-JOB handler 配置。
- 支持调度服务拉取待同步规则，并向 XXL-JOB 管理端同步。
- 支持 XXL-JOB 触发 dataCollectJobHandler 后解析调度参数，回调后端派发规则。
- 支持调度任务列表、调度任务详情、创建调度任务和调度触发日志查询。

### 10. 运维监控与平台管理模块

- 支持项目、需求、任务组、采集任务、运行任务、补采请求等 dashboard 指标。
- 支持任务状态分布和数据状态分布统计。
- 支持运维监控摘要，包括健康分、任务完成率、数据采集率、验收率、服务健康和风险卡片。
- 支持 Demo 数据初始化和重置，方便联调、演示和回归验证。
- 支持运行中心、调度页面、监控页面等前端入口，形成面向运营和排障的管理视图。

### 11. 前端产品化页面模块

- 已建设项目、需求管理、采集任务管理、数据验收、知识库、运行中心、调度、监控、系统配置、个人中心等主菜单入口。
- 需求详情页集成需求定义、采集任务、任务输出、质量稽核、数据验收等关键视图。
- 采集任务页支持任务组卡片、任务实例表、任务执行操作、试运行弹窗、Prompt 管理和输出结果查看。
- 系统配置页支持模型配置和权限配置。
- 前端统一进行 snake_case 与 camelCase 映射，降低后端接口格式对页面组件的侵入。

## 四、工程治理与可持续迭代能力

### 1. 分层架构与领域拆分

后端逐步从早期集中式 Controller/Service 形态，演进为 interfaces、application、domain、infrastructure 等分层结构。项目、需求、任务、调度、目标表、账号等领域具备更清晰的模型、仓储和应用服务边界，为后续复杂业务规则沉淀提供了基础。

### 2. 数据库演进与迁移脚本

平台维护了 baseline、增量升级、索引优化、采集结果、指标映射、目标发布、验收单、调度规则、调度触发日志、XXL-JOB 同步字段等迁移脚本。数据库结构能够支撑从需求定义到结果发布的完整数据链路。

### 3. 联调和回归验证基础

仓库内已沉淀前端单测、后端领域服务测试、调度服务测试和 smoke 脚本，覆盖任务计划、任务执行、调度回调、状态映射、需求数据管线等关键场景，为后续持续迭代和问题回归提供支撑。

## 五、阶段性总结

上半年平台建设完成了从“采数需求页面原型”到“数据生产闭环平台”的关键跨越。核心价值体现在三方面：

1. 业务对象闭环：需求、宽表、任务、结果、验收、发布之间已建立可追踪的数据关系。
2. 执行链路闭环：任务计划、采集触发、状态同步、结果入库和物化回填已具备完整链路。
3. 工程体系闭环：前端、后端、调度、Agent、数据库和公共契约已形成可扩展的多服务基础。

后续工作可在此基础上继续增强真实采集算法接入、质量规则体系、目标表发布策略、权限细粒度控制、调度稳定性和生产级监控告警能力。
